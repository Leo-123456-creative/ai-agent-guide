01 / THE CORE

让 Agent 变强的
五个控制旋钮

提示词只是入口。真正的杠杆，是任务定义、上下文质量、工具能力、验证机制和权限边界。

01 / INTENT明确目标
02 / CONTEXT合适上下文
03 / ACTION对的工具
04 / PROOF结果可检查
05 / BOUNDARY权限有边界
核心公式：明确目标 + 合适上下文 + 对的工具 + 可验证结果 + 适度自主权。不要一开始就堆多 Agent；先证明简单流程不够用。
02 / LEVEL UP

五级进化路线

不是“懂不懂代码”的分级，而是从单次回答进化到可复用、可衡量的工作流。

会提需求

讲清目标、背景、限制和验收标准；模糊任务先拆解。

EXAMPLE / 把需求变成方案

会搭流程

研究、起草、核查分步骤进行，每一步都有明确产出。

EXAMPLE / 来源 → 报告 → 核验

会给上下文

提供文件、样例、规则和历史决策，减少凭空猜测。

EXAMPLE / 用真实样例校准风格

会用工具

让 AI 搜索、读文档、分析表格或操作项目；不是只聊天。

EXAMPLE / 监测、整理、分析

会设计 Agent

加入记忆、权限、分工和评测，让工作可重复并能处理失败。

EXAMPLE / 可审计的工作系统
上下文工程：不是把资料全塞进对话，而是按需取用、压缩重复信息、保留关键决策与未完成事项。参考 Anthropic 的上下文工程指南 ↗。
03 / UNCOMMON USE

跳出“帮我写一篇”

把 AI 变成你的流程设计师、对手、审计员和学习搭档。

01 / SOP MINING

把经验提炼成个人 SOP

喂给 AI 你做得好的报告、方案和邮件，让它归纳检查清单、模板与例外处理规则。好样例胜过一长串形容词。

↗
02 / QUESTION DESIGN

让它先找“关键未知数”

在做决定前，让 AI 找出结论依赖哪些变量、缺少哪些事实，以及什么证据会改变建议。

↗
03 / RED TEAM

用不同角色拆穿盲点

让支持者、反方、执行者和风险审查者分别看同一方案。最终输出争议点和证据，而不是投票。

↗
04 / SHADOW MODE

先做“影子 Agent”

先只读资料、只生成草稿，不发送、不修改。对比建议与最终决定，发现错误后再逐步开放权限。

↗
05 / PERSONAL EVALS

建立你的真实任务测试集

存下 10–20 个常见任务和你认可的答案。改提示或换模型后，用同一批任务比正确率、成本和遗漏。

↗
06 / PROOF OF DONE

把“完成”变成验收条件

要求每条行动有负责人和日期；不确定就标待确认；关键事实给出处。漂亮不等于正确。

↗
04 / WEEKLY LOOP

每周 30 分钟
形成自己的情报闭环

别被“新品发布”牵着跑。看完资讯，必须能转成一个低风险实验。

STEP 01

看一条官方更新

搞清楚新功能实际能做什么，以及需要什么工具或权限。

STEP 02

看一条实测或研究

区分产品演示、基准成绩和真实工作表现，不把宣传语当结论。

STEP 03

看一条风险或失败案例

关注权限、隐私、成本、误操作和责任归属。

STEP 04

做一个自己的小实验

用真实但低风险的任务测试，然后记下效果、成本和失败点。

快速判断新闻价值：新增了什么能力？有没有独立或可复现的测试？代价是什么？我能用一个小任务验证吗？

07 / SAFETY LAYER

能力越强，边界越要清楚

把 Agent 当成会犯错、会读到不可信内容、也可能误用工具的协作者。

✓ 推荐默认设置

  • 最小权限：只开放当前任务需要的工具和数据。
  • 先只读、先草稿；发送、购买、删除等动作需确认。
  • 重要结果留痕：来源、工具、修改和检查记录可追踪。
  • 用低风险任务试运行，观察成本、重试和失败方式。

! 特别留意

  • 邮件、网页、文档里的文字可能是不可信指令，不应扩大 Agent 权限。
  • 私人数据 + 不可信内容 + 对外发送能力，组合风险尤其高。
  • 不要把一次成功当可靠；重复测试并检查异常情况。
  • 高影响决定保留人工审核，不能只靠提示词保证安全。
